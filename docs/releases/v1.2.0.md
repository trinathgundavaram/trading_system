## Why this release exists

§4 replaced nine inline token checks with a `require_token` dependency, on the
stated reasoning that "a dependency cannot be forgotten on a new endpoint the
way an inline if-statement can — and that is the specific mistake that turns a
tenth write route into an unauthenticated one."

It was then applied to seven routes and not to the other eight, which had never
had a check to replace. `scripts/verify_phase1.py` reported them as an accepted
warning across two releases. They are write endpoints on a process that also
holds brokerage credentials, and the argument for guarding them is the same
argument §4 already made.

## What changed

### server.py — the last eight write routes

| Route | What it does unauthenticated |
|---|---|
| `/api/cycle/run_now` | triggers a full scan cycle |
| `/api/cycle/cancel` | kills a cycle mid-flight |
| `/api/backtest/run` | starts a multi-month replay |
| `/api/analytics/threshold_regret/run` | starts a re-simulation |
| `/api/ticker/validate` | calls the yfinance MCP |
| `/api/ticker/evaluate_now` | runs a full scoring pass |
| `/api/alerts/{id}/resolve` | mutates alert state |
| `/api/prompt/copy` | shells out to `pbcopy` |

All eight now carry `_: bool = Depends(require_token)`. **15 of 15 write routes
are guarded.**

`/api/cycle/run_now` is the one that mattered most: with the §2 gates open it
reaches the order path. It was inert in practice — the gates are shut, the
receipt is absent and the bind is loopback — but "inert because three unrelated
things happen to be true" is not a control.

### ui/index.html — one helper, not eight edits

`authFetch(url, opts)` attaches the header, and is the client-side mirror of
`require_token`: one place to get right rather than fifteen. It also centralises
the two failure responses — a 403 clears the cached token so the next attempt
re-prompts instead of failing silently forever against a stale value, and a 429
is reported as the lockout it is rather than as a wrong password.

The seven call sites that already set the header by hand were left alone. They
are correct, and rewriting working authentication code in a patch release is
how patch releases become incidents.

### Three call sites that would have misreported an auth failure

Found while wiring this up, all pre-existing:

- `/api/ticker/validate` — the `{detail: ...}` error body fell through to
  `!data.valid`, so a rejected request told you the **ticker was invalid**.
  Actively misleading: you would go and check the ticker.
- `/api/alerts/{id}/resolve` — the response was discarded entirely, so a
  rejected request still toasted "Alert dismissed" and removed the row from
  the UI while the alert stayed open in the database.
- `/api/prompt/copy` — fell through to a generic "Copy failed", stacking a
  second misleading toast on top of the real one.

### saveConfig's default

`saveConfig(update, needsAuth=false)` → `needsAuth=true`. All twelve call sites
already pass `true` explicitly, so **no behaviour changes**. It removes a
footgun of exactly the kind this release exists to close: a thirteenth caller
that forgot the flag would have sent no token and got an opaque 403. A safety
parameter must not default to off.

## What this does NOT change

- No scoring, sizing, threshold or exit logic. `decision_function_changed:
  false`, fingerprint unchanged, v1.0.x and v1.1.0 data remain poolable
- No schema change
- The token itself. **`UI_AUTH_TOKEN` is still the retired 5-character value**
  — see Known issues
- Read routes stay open, deliberately. The dashboard must render before anyone
  has typed a token

## Behaviour you will notice

- The first time you press **Run now**, **Cancel run**, **Run Backtest**, add a
  ticker, dismiss an alert or copy the prompt, you will be asked for the auth
  token if you have not already entered one this browser. It is cached in
  `localStorage` afterwards, so this is once per browser, not once per click
- A wrong token now clears itself and re-prompts rather than failing repeatedly
- Six failed attempts in five minutes returns 429 for fifteen minutes, and the
  UI says so
