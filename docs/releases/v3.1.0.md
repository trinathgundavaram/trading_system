## Why this release exists

A full click-through audit of the web UI — every tab, both books, every control
— found that the interface was confidently stating things that were not true.
Not cosmetic drift: the Monitor tab reported "NO DATA YET" for all fourteen data
sources while the health table sat fully populated; the Signals tab labelled 42
tickers `HOLD` when none of them had been scored at all; the Real Portfolio tab
displayed cash under the heading "total portfolio value"; and four separate
strings still told the operator this app never places orders, on a build where
`engine/live_trader.py` can.

The common shape is a UI that fails silently in the reassuring direction. A
monitoring panel that cannot report a problem is read as "no problem". That is
what this release fixes, plus the storage-layer bug underneath one of them and
the missing audit trail underneath another.

## What changed

### Silent failures

- `get_source_health()` returned `[]` unconditionally on Postgres —
  `storage/database.py:_PGCursorWrapper` implemented `fetchone`/`fetchall`/
  `rowcount`/`lastrowid` but not `description`, the tree's only
  `cur.description` caller, and the `AttributeError` was swallowed by a bare
  `except Exception: return []` annotated "table not created yet". Monitor's
  Data Sources panel had shown NO DATA YET for all 14 sources since the v3.0
  Postgres migration, with nothing in the logs.
- `/api/logs` sorted merged lines by their whole text — `server.py:get_logs` —
  which is only correct for lines beginning with a timestamp. Traceback frames
  carry none, so they sorted by their own content: identical frames from
  unrelated failures clustered together and `Traceback (most recent call
  last):` appeared with no frames beneath it. Now carries the last-seen
  timestamp forward per source and sorts on `(ts, source, position)`.
- `close_position()` discarded the exit price, exit time and computed P&L of
  every close, persisting only `status='closed'` — `storage/database.py`. The
  real book therefore had no per-trade audit trail at all, which is why a
  −$369.91 all-time realized figure could not be traced against a ledger whose
  only completed real round trip made +$0.09.

### Data integrity

- `close_position()` now refuses a non-positive `exit_price`. It previously
  accepted `0`/`None` and computed `(0 - entry) * shares == -cost`, booking an
  entire cost basis as a realized loss — the most plausible mechanism by which
  a small book records a large negative number.
- Its closing `UPDATE` was scoped by `ticker + status` while the `SELECT` above
  it took only the newest row (`ORDER BY id DESC LIMIT 1`). A duplicate open
  row would have been closed with no P&L recorded. Now scoped by `id`.
- `positions` gains `exit_price`, `exit_time`, `realized_pnl`, `closed_by`.
- Real account value read portfolio CASH — `server.py:_robinhood_account_probe`
  resolved it through `("equity", "portfolio_cash", …)` first-non-empty, but
  `load_account_profile()` has no `equity` key; equity lives on
  `load_portfolio_profile()`. Verified against the broker: cash $1,859.94,
  holdings $144.21, true total $2,004.15 — and $1,859.94 is what the tab showed.
- `main.py --ui` ignored `TP_UI_PORT` and passed a hardcoded `8080` to
  `_free_ui_port()`, whose job is to kill whatever holds that port. `tp run
  <tag> --ui` would have killed the PRIMARY version's UI and taken 8080 — the
  cross-version collision `scripts/tp` exists to prevent.

### New surfaces

- **Execution Posture** panel (Control) — surfaces `live_trading_armed`,
  `execution_path`, `orders_breaker_open`, `read_ok` and the backtest
  `validation` receipt. A repo-wide grep found zero references to any of them
  in `ui/index.html` before this; `orders_breaker_open` in particular means
  real orders are being silently skipped, and was invisible.
- **Broker Reconciliation** panel + `GET /api/real/reconcile` — compares the
  local real book against the configured account. `positions` has no account
  column and `engine/account_sync.py` imports through a robin_stocks call that
  only sees the primary account, so positions from different accounts merge
  silently. Reports only; mutates nothing.
- Veto summary on the Dashboard — distinguishes "the strategy found no setups"
  from "the strategy never ran".
- Monitor now shows `kill_reason` and the running cycle `pid`.

### Interface

- Hash routing (`#tab`, `#tab/book`) — reload, restore-session and the back
  button previously all landed on the Dashboard regardless of where you were.
- Light theme, "indigo on warm paper": indigo owns interaction, green/red own
  money, warm surfaces and warm near-black text.
- Filter row rebuilt — borderless until hovered/focused, styled select
  chevrons, active filters as removable chips with a row count.
- Chart.js removed: fetched from a CDN on every page load, never used (the
  file contained one occurrence of the string "Chart" — the script tag).
- Corrected four strings asserting this app never places orders; reconciled
  "6-bucket" vs "7-bucket" and the portfolio-heat caption vs its tooltip.

## What this does NOT change

**No scoring, sizing, exit or veto logic.** `rules/` is untouched; no
`DECISION_PATHS` file appears in the diff; `config.yaml` is unmodified.
`classify_change.py` reports MINOR. Trade history from v3.0.0 pools with this
release — they are the same strategy.

No live-execution gate is opened, relaxed or re-ordered. The arming path still
requires all of: `TP_FORCE_PAPER` unset, `live_execution_enabled`, a current
validation receipt, `watch_execute: EXECUTE`, and `auto_trade: true`.

## Behaviour you will notice

- Monitor's Data Sources panel populates for the first time since v3.0.0.
- The Signals tab shows `VETOED` and `HOLDING` where it previously showed
  `HOLD` for everything.
- Real account value increases by the market value of your holdings — the old
  figure was wrong by exactly that amount.
- The Real Portfolio tab may show a Broker Reconciliation warning. That is
  pre-existing data being surfaced, not something this release caused.
- `close_position()` now returns `{}` and logs an error where it previously
  accepted a zero exit price. Any caller relying on that silently succeeding
  will now fail loudly, which is the intent.
- Browser reload keeps your tab.

## Database changes

No Alembic migration. Four additive columns on `positions`
(`exit_price REAL`, `exit_time TEXT`, `realized_pnl REAL`, `closed_by TEXT`)
created via `_add_column_if_missing()` at startup. NULL on every pre-existing
row, which is the useful signal — those are exactly the closes that cannot be
audited.

Additive only, so **v3.0.0 can still read a database this version has
migrated**. Backward SQL, if ever needed:

```sql
ALTER TABLE positions DROP COLUMN exit_price;
ALTER TABLE positions DROP COLUMN exit_time;
ALTER TABLE positions DROP COLUMN realized_pnl;
ALTER TABLE positions DROP COLUMN closed_by;
```

## Known issues carried forward

- **Positions are not attributable to a Robinhood account.** `positions` has no
  account column, so a real book can merge holdings from more than one account.
  v3.1.0 makes this visible via Broker Reconciliation but does not fix the
  schema. A position bought in the primary account before
  `account.robinhood_account_number` was pointed elsewhere still counts toward
  this book's market value, unrealized P&L, invested cost and portfolio heat.
- **`daily_stats.realized_pnl` may hold unattributable history.** Rows written
  before the audit-trail columns existed cannot be traced to the closes that
  produced them. `scripts/audit_realized_pnl.sql` reports what is traceable;
  `scripts/cleanup_test_pnl.sql` clears the 2026-07-24 test session reversibly.
- **Sentiment scoring is directionally unreliable.** Observed during the audit:
  "AST SpaceMobile Stock (ASTS) Crashes After Disclosing a $1B Offering" scored
  `bullish`. Display is correct; the scorer is not. Not addressed here.
