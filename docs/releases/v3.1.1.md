## Why this release exists

Deploying v3.1.0 broke the deploy. `./service.sh restart` killed the running UI
and then failed to start a replacement, leaving the machine with no UI at all:

```
restart ui
  not running: com.tradingplatform.ui
  port 8080 still held by a previous UI process (PID 64255) - terminating it
  ERROR: no plist at .../com.tradingplatform.ui.plist
```

`_free_ui_port()` is destructive by design — its whole job is to kill whatever
holds the port. It ran on `install`, `start` and `restart`, but only `install`
writes a plist. So on any host where a service had never been installed, the
port was cleared for a replacement that could never be bootstrapped.

That ordering has been there since `_free_ui_port()` was introduced. v3.1.0's
improved error message is what made it visible; previously the failure arrived
as a `CalledProcessError` traceback and the killed process went unmentioned.

## What changed

### Service management

- `_free_ui_port()` now runs only when the service is actually installed —
  `scripts/services.py:main` — and says so when it declines. `install` is
  always safe because it writes the plist itself.
- `LaunchdManager.start()` — `scripts/services.py` — checks the plist exists
  before bootstrapping, retries once after an unconditional `bootout`, and
  otherwise diagnoses the failure instead of raising:
  - missing plist → tells you to run `install`
  - disabled label → detected via `launchctl print-disabled`, with the
    `launchctl enable` command
  - plist naming an interpreter that no longer exists → the version-switch
    case, since `_commands()` bakes `sys.executable` into the plist
- `SystemdManager.start()` — same `check=True` traceback problem, same
  treatment, so both platforms fail identically.
- New `ServiceManager.is_installed()`, defaulting to `True` — `main()` had
  begun calling the launchd-only `plist_path()`, which would have raised
  `AttributeError` on Linux and Windows.

## What this does NOT change

No runtime code. `server.py`, `scheduler.py`, `engine/`, `rules/` and
`storage/` are untouched — this release only alters the scripts that install
and start those processes. `classify_change.py` reports PATCH.

No live-execution gate is opened, relaxed or re-ordered.

## Behaviour you will notice

- `./service.sh restart` on a never-installed service now leaves the running
  process alone and tells you to run `install`, instead of killing it.
- launchd and systemd failures print a diagnosis and a command, not a Python
  traceback.
- `./service.sh restart` with everything installed behaves exactly as before.

## Validation

- `scripts/release.sh patch` gates: pytest, `check_deps.py`,
  `check_config_secrets.py`, `verify_phase1.py --release`, `verify_phase2.py`,
  `reconcile.py`.
- Four stubbed-launchctl cases exercised directly, all passing without raising:
  missing plist; exit 5 cleared by retry; disabled label; plist pointing at a
  dead interpreter.
- Regression test for the ordering fix: `restart ui` with no plist must not
  call `_free_ui_port()`; with a plist present it must, exactly as before;
  `install` must always free the port.

Backtest receipt: not re-run, not required — `decision_function_changed: false`
and no runtime code changed.

## Rollback

```bash
./scripts/tp promote v3.1.0
```

Rolling back reinstates the ordering bug. If you do roll back, run
`./service.sh install ui` rather than `restart` on any host where the service
is not already installed.

## Known issues carried forward

Everything listed under v3.1.0 still applies: positions are not attributable to
a Robinhood account, `daily_stats.realized_pnl` may hold unattributable
history, and sentiment scoring is directionally unreliable.
