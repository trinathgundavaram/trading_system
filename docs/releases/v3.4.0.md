## Why this release exists

Two independent lines of work landed on `main` since v3.3.0 and neither was
ever tagged: dynamic position sizing (2026-07-27), and a same-day pass fixing
a live paper-account accounting bug plus adding operational tooling that was
missing when it turned out to be needed (backtest abort, running-version
visibility). `scripts/release.sh` tags everything since the last ref, so
both ship together as v3.4.0 rather than as separate releases.

## A note on the version bump

`scripts/classify_change.py` reports **MAJOR** against v3.3.0. That verdict
is entirely `engine/position_sizing.py` — explicitly listed in
`DECISION_PATHS` because position SIZE is part of this file's own definition
of the decision function ("a buy, a size, or an exit"). This tag ships as
**minor** anyway, overriding that flag deliberately rather than by omission:
`use_dynamic_sizing` defaults to `false` in `config.yaml`, so no trade —
real or paper — is sized any differently under v3.4.0 than it was under
v3.3.0 unless someone explicitly opts in. The classifier is right that the
CODE PATH is decision-relevant; the override rests entirely on the DEFAULT
behavior being unchanged and nothing having opted in yet.

**This is a one-tag grace period, not a standing exemption.** The day
`use_dynamic_sizing: true` ships in a live `config.yaml`, pre/post trade
history stops being poolable from that point forward — treat that config
change, whenever it happens, as the real decision-function boundary, not
this tag.

Everything else in this release — `engine/paper_trader.py`, the backtest
abort switch, the version endpoint — touches none of
`rules/swing_buy_rules.py`, `rules/sell_rules.py`, `rules/exit_scorer.py`,
`rules/dynamic_thresholds.py`, `rules/hard_vetoes.py`, or `config.yaml`'s
decision keys, and would be unambiguously PATCH/MINOR released on its own.

## What changed

### Dynamic Position Sizing (`engine/position_sizing.py`, `scheduler.py`)

Position size now calculates as a percentage of current portfolio instead of
a fixed dollar amount:

```
Position size = Portfolio Total × Position Size % ÷ 100
Position size = $60 portfolio × 3% ÷ 100 = $1.80 per trade
Position size = $300 portfolio × 3% ÷ 100 = $9.00 per trade (scales automatically)
```

- New: `engine/position_sizing.py:_get_portfolio_total()` — sums open
  position value.
- Modified: `engine/position_sizing.py:calculate()` — accepts a `db`
  parameter for the dynamic calc.
- `scheduler.py` — passes `db` through to the sizing engine.
- Disabled by default (`use_dynamic_sizing: false`); falls back to static
  `trade_size_usd` when off or on an empty first trade.
- Tests: 6 new unit tests in `tests/test_dynamic_sizing.py`.
- See `DYNAMIC_SIZING.md` (user guide) and `DYNAMIC_SIZING_IMPLEMENTATION.md`
  (technical detail).

### Fixed — paper account showed more than its $10,000 basis; SEED tickers visible in paper mode

**Root cause**: `engine/paper_trader.py`'s `ensure_seeded()` cloned every
open real position into the paper book (`trade_mode='SEED'`) on the first
WATCH-mode cycle, logging each as a "buy" in `paper_trades` but never
debiting `paper_account.cash` for it — unlike the manual
`robinhood_sync.py seed-paper` CLI, which correctly rebases `starting_cash`
to include the mirrored cost. SEED positions sat on top of the $10,000
purse for free: extra total value, plus a `reconcile.py` "paper cash
disagrees with the trade ledger" finding equal to the exact cost of
whatever was open in the real book at seed time. Found live via a fresh
diagnostic (below) — traced a $240.11 drift to exactly 4 uncosted SEED rows.

- `engine/paper_trader.py` — `ensure_seeded()` no longer clones real
  positions into the paper book at all; it only creates the cash purse.
  `robinhood_sync.py seed-paper` is unchanged and still available for
  anyone who explicitly wants a cost-correct real-account mirror.
- `scripts/fix_uncosted_seed_positions.py` (new) — one-time cleanup for
  SEED rows created by the pre-fix code path. Deletes the position and its
  `seeded_from_real_portfolio` ledger row without touching cash, since cash
  was never debited for them in the first place. Dry run by default,
  `--apply` to write.
- `scripts/diagnose_cash_drift.py` (new) — read-only breakdown of a
  `reconcile.py` cash-ledger drift by `reason` and `trade_mode`, plus the
  most recent ledger rows, for tracing any future drift to its source
  without inventing numbers.

### Added — abort switch for a runaway backtest subprocess

The scan cycle has had a hard kill switch (`/api/cycle/cancel`,
`engine/cycle_supervisor.py`) since 2026-07-22; the backtest subprocess
(`run_backtest.py`, spawned by `engine/backtest_loop.py`) had none, because
nothing recorded its PID anywhere reachable — found live, when a backtest
had been running long enough to need aborting and there was no way to do it
short of `ps`/`kill` by hand.

- `storage/database.py` — new `backtest_runs.pid` column, captured via
  `os.getpid()` in `log_backtest_run_start()` (the row is always created by
  the process actually doing the replay, regardless of which of the three
  call paths started it — weekly auto-trigger, the Learning tab button, or
  the bare CLI).
- `engine/backtest_loop.py` — new `kill_running_backtest()`, reusing
  `cycle_supervisor`'s portable SIGTERM→grace→SIGKILL process-group kill
  rather than a second implementation of the same primitive.
- `server.py` — new `POST /api/backtest/abort`.
- `ui/index.html` — new "Abort backtest" button on the Learning tab,
  visible only while a run is in progress.
- `storage/database.py` — new `reap_stale_backtest_run()`: a crashed/killed
  backtest that never reaches `log_backtest_run_complete()`/
  `log_backtest_run_failed()` used to leave its `backtest_runs` row stuck at
  `status='running'` forever — found live, a run with no OS process behind
  it (`ps aux` showed nothing). Liveness-checked via the new `pid` column
  (`psutil.pid_exists`), not a time guess, so a genuinely long-running
  replay is never touched. Wired into `/api/backtest/status` and
  `/api/backtest/run` so a stale row self-heals instead of permanently
  409-blocking the next run.

### Added — running code version shown in the UI

- `server.py` — new `GET /api/version`: reads the `VERSION` file (the same
  source `scripts/version.py --current` uses) plus, best-effort, the git
  commit and whether HEAD has moved past that tag.
- `ui/index.html` — shown in the sidebar under the brand name, fetched once
  at boot.

## What this does NOT change

No scoring, sell-rule, or veto logic moved — `rules/swing_buy_rules.py`,
`rules/sell_rules.py`, `rules/exit_scorer.py`, `rules/dynamic_thresholds.py`,
`rules/hard_vetoes.py`, and `config.yaml`'s decision keys are untouched.
`engine/position_sizing.py` did change (see the version-bump note above),
but ships disabled.

## Behaviour you will notice

- Nothing changes for an existing account with `use_dynamic_sizing` unset
  (defaults `false`) until `scripts/fix_uncosted_seed_positions.py --apply`
  is run — see Action Required.
- A fresh paper account (`ensure_seeded()`) no longer shows any SEED-tagged
  tickers; it starts as a plain cash purse.
- The Learning tab's Historical Replay panel gets an "Abort backtest"
  button, visible only mid-run.
- The sidebar shows the running `VERSION` (and git commit, if resolvable)
  under the brand name.

## Config changes

```yaml
trading:
  use_dynamic_sizing: false             # new key, default false (opt-in)
  position_size_pct_of_portfolio: 3.0   # new key, only read when the above is true
```

No existing keys changed meaning.

## Database changes

- `backtest_runs.pid INTEGER` — additive column via
  `_add_column_if_missing`, applied automatically on next `Database()`
  construction. No backfill; existing `running` rows read `pid IS NULL` and
  are treated as stale by `reap_stale_backtest_run()`.
- No migration file, no `migrations/` entry needed — same pattern as
  `cycle_status.pid`.

## Action required after upgrading

1. `python3 scripts/fix_uncosted_seed_positions.py --apply` — one-time,
   clears any SEED positions cloned by the pre-fix `ensure_seeded()`.
   Safe to run even if there are none (no-ops).
2. `python3 scripts/reconcile.py` — confirm the cash-ledger drift clears.
3. `./service.sh restart` — picks up the backtest-abort/self-heal code and
   the version endpoint. Any backtest stuck at `status='running'` from
   before this deploy has no `pid` recorded and self-clears on the first
   `/api/backtest/status` poll after restart — no separate manual step.

## Rollback

```bash
./scripts/tp promote v3.3.0
```

Rolling back reinstates: uncosted SEED cloning on a fresh paper seed (the
bug this release fixes), no backtest abort switch, no stale-run self-heal,
and no version display. `backtest_runs.pid` is additive — v3.3.0 code
ignores the column, so rolling back is schema-safe with no migration
concerns in either direction. If dynamic sizing was ever turned on before
rolling back, turn it off first; v3.3.0 has no such config keys.
