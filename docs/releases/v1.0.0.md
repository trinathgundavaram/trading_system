## Why this release exists

To fix a reference point. Every measurement in the evaluation report — the
−0.75% expectancy, the 0-trade backtest, the score distribution that never
reaches the sizing tiers — describes this exact tree. Until it is tagged, those
numbers describe nothing recoverable, and no later change can be shown to be an
improvement rather than a coincidence.

This is a baseline, not a good release. It is committed as-is, including its
defects, because a tidied-up baseline would no longer be the thing that was
measured.

## What changed

Nothing. First tracked commit.

Two files were touched before the commit was made, and only because leaving
them as they were would have put a secret in the history or left the system
armed while two days of repository work went on around it:

- `config.yaml` — `auto_trade: false`, `watch_execute: WATCH`,
  `live_execution_enabled: false` (§2, step 0.1)
- `config.yaml` — the Robinhood account number and UI auth token replaced with
  `${RH_ACCOUNT_NUMBER}` / `${UI_AUTH_TOKEN}` (§3, §34.3, step 0.2)

## What this does NOT change

The decision function, the scoring weights, the thresholds, the stop machine,
the position sizing, and the database schema are all untouched. A backtest run
from this tag reproduces the evaluation report's numbers exactly.

## Behaviour you will notice

The system will not place a live order. That is the only observable difference
from the tree as it stood on the morning of 2026-07-24.

`config_loader` now raises at startup if `RH_ACCOUNT_NUMBER` or
`UI_AUTH_TOKEN` is missing from the environment. This is deliberate: an empty
auth token compares equal to a blank Authorization header and would silently
unauthenticate every write endpoint on the UI.

## Config changes

| `trading.auto_trade` | `true` | `false` | none |
| `trading.watch_execute` | `EXECUTE` | `WATCH` | none |
| `trading.live_execution_enabled` | `true` | `false` | none |
| `account.robinhood_account_number` | literal | `${RH_ACCOUNT_NUMBER}` | set it in `.env` |
| `ui.auth_token` | literal | `${UI_AUTH_TOKEN}` | set it in `.env`; rotate the value |

## Known issues carried forward

All of them. R-1 through R-6, E-2 through E-10, T-1 through T-9. See
CHANGELOG.md for the shortlist that makes this tag unsafe to run armed, and the

tags runnable and this tag's committed config had all three gates open;
`TP_FORCE_PAPER=1` (§38.4) is what prevents `tp run v1.0.0` from reproducing an
armed system along with the results.
