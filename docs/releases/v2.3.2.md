## Why this release exists

v2.3.1's port fix was in the wrong layer, and the loop it was written to stop
was still running when this was tagged.

`_free_ui_port()` was called from `scripts/services.py`'s `install`, `start`
and `restart` verbs. That covers `./service.sh restart` — a human deciding to
restart. It does not cover the launcher that was actually producing the
relaunches: **launchd's `KeepAlive` re-executes `main.py --ui` directly.** It
never re-enters `services.py`, so it never called the cleanup. Same for
systemd's `Restart=` and Windows Task Scheduler, which is the portability
promise §45 exists to keep.

So the loop was self-sustaining and immune to the fix: one orphaned UI held
8080, launchd spawned a replacement every few seconds, and each replacement
printed the complete startup banner — `TRADING PLATFORM - WEB UI`,
`Serving http://127.0.0.1:8080`, the execution posture, the validation line —
before dying on `[Errno 48]`. The log therefore reads like a server starting
normally, repeatedly, which is precisely why 342 iterations went unnoticed.

## What changed

- **The reclaim now guards the bind itself** — `main.py:run_ui()`, between
  `banner.print_banner()` and `uvicorn.run()`. That is the one placement every
  launcher passes through: launchd, systemd, Task Scheduler, `run.sh --ui`, and
  a bare `python3 main.py --ui`. `services.py` keeps its copy, which is now
  belt-and-braces rather than the only line of defence.

- **Wrapped so it can never block startup.** A missing `scripts/`, no `lsof`,
  no `netstat` — any failure prints a note and proceeds to the bind. The
  cleanup is a convenience; refusing to start because it could not run would be
  a worse bug than the one being fixed.

- **Two tests that assert placement, not just behaviour** —
  `TestStaleUiPortIsReclaimed`. One checks `_free_ui_port` appears before
  `uvicorn.run(` in `run_ui()`'s body; the other checks it is inside a
  `try`/`except`. Behavioural tests on `_free_ui_port` already passed at
  v2.3.1 and did not catch this, because the function was correct and simply
  unreachable from the path that mattered. The lesson generalises: eight tests
  proving a helper works say nothing about whether the code under test calls
  it.

## What this does NOT change

- Decision function, schema, live-execution posture: all unchanged.
  `config_fingerprint` still `cc9a149613427f56`; `classify_change.py` says
  PATCH.
- `_free_ui_port()`'s own logic is untouched from v2.3.1 — it still refuses to
  kill a process whose command line does not look like our UI, and still
  escalates SIGTERM to SIGKILL.

## Behaviour you will notice

- A relaunched UI reclaims the port on its own and comes up serving, instead of
  banner-then-die.
- **If you run both a launchd UI job and `run.sh --ui`, they will now fight** —
  each looks like "our UI" to the other, so whichever starts last wins the
  port. That is the same behaviour `run.sh` has had since 2026-07-14, and one
  UI winning is a better failure than a permanent relaunch loop. Do not run
  both.

## Rollback

```bash
./scripts/tp promote v2.3.1
```

Reinstates the gap, so an automatic relaunch can loop again. Break it with:

```bash
kill $(lsof -ti tcp:8080 -sTCP:LISTEN)
```
