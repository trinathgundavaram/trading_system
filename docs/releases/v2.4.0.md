## Why this release exists

A request to check the documentation against the code, which turned up one
claim that was dangerous, one that was hiding a live defect, and a handful that
were merely old.

The audit read every "not implemented" / "placeholder" / "not wired" /
"deferred" statement in `README.md`, `CHANGELOG.md`,
`BUILD_FROM_SCRATCH_GUIDE.md`, `pre_selection_criteria_and_trading_modes.md`,
`prod_readiness_plan.md` and `docs/`, and checked each against the code it
describes. `BUILD_FROM_SCRATCH_GUIDE.md` and `docs/trayd.md` came back clean —
notably, `trayd.md` states correctly that `engine/live_trader.py` is the
platform's only sanctioned order path, which is exactly the fact README denied.

## The one that mattered

**README.md's first three paragraphs said this codebase cannot place orders.**

Verbatim: `auto_trade` is "not implemented at all", "nothing in this codebase
places live orders", and this code "never places, modifies, or cancels an
order."

`engine/live_trader.py` is 32KB of order placement. It logs into Robinhood via
`robin_stocks`, checks buying power, submits fractional market buys and sells,
waits for fills, and handles rotation sells. The string `live_trader` did not
appear anywhere in README.md.

Everything is gated — `TP_FORCE_PAPER`, `live_execution_enabled`, a current
validation receipt, `watch_execute: EXECUTE`, `auto_trade`, all five required —
and shipped config has them closed. But **"disarmed by configuration" and "not
built" are different statements**, and a reader who believes the second will not
check the first before changing a config value. That is the specific failure
this correction is for.

Replaced with the actual gate table and a visible note that the previous claim
was wrong. Not a silent edit: someone who has read this file before has a false
belief that needs contradicting, not quietly overwriting.

## The one that was hiding a defect

README described the pattern database's ADX, CMF, market breadth, anchored
VWAP, industry RS, unusual options and sector RS as "0.0/neutral defaults
throughout the codebase". That framing — *the source data is fake* — is what
made this look like a known limitation rather than a bug, and it is why nobody
looked.

The sources are real, and have been for several sessions.
`engine/ticker_analyzer.py`'s `_calc_indicators` computes ADX, CMF, the TTM
squeeze and the swing-low AVWAP from the same daily bars as every other
indicator; `engine/market_breadth.py` computes sector RS and the opex calendar.
`engine/ticker_data_adapter.py` was updated each time one landed.
`engine/pattern_features.py` never was, so it kept writing `0.0` / `False` /
`"normal"` for seven features — while the real values sat in the caller's own
scope, one argument away.

Four of the seven are numeric and four are in `NUMERIC_FEATURES`; three are in
`CATEGORICAL_FEATURES`. The categorical ones were doing active harm: a constant
one-hot value means *every* pattern pair matches on that dimension, which
inflates cosine similarity uniformly and pushes unrelated setups over
`SIMILARITY_THRESHOLD_BY_COUNT`. The similarity search was getting less
discriminating, not merely no better.

## Why the writer fix alone would have made things worse

This is the part that took the actual work.

While every row in `patterns` held `adx = 0.0`, that column's standard
deviation was zero, `_encode_patterns` clamped it to 1.0, and every row encoded
to exactly 0.0. Useless — but symmetric, and harmless.

Start writing real ADX readings (typically 15–40) and the column acquires a
real mean. Every historical `0.0` then z-scores to a large negative number. The
old rows do not stay uninformative; they begin asserting **"extremely low
ADX"** — a measurement nobody ever took. A new low-ADX setup would then match
confidently against a cohort whose only shared property is predating the fix.
The learning backend would have gotten quietly, confidently wrong, with no
error anywhere.

So rows are now stamped with `feature_schema`, and `_encode_patterns` treats
the seven affected features on unstamped rows as **missing rather than
measured**:

- numeric → `NaN` through a nan-aware mean/std, then imputed to the column mean,
  which is exactly `z = 0` — the honest encoding for "this row tells us nothing
  about ADX";
- categorical → a distinct `__unrecorded__` bucket, so a stale `False` cannot
  be counted as evidence of "no squeeze".

`config_fingerprint` is deliberately **not** touched. It answers "was this row
produced by a different strategy?", and the strategy did not move — only the
fidelity of what was recorded about it. Folding the schema into that hash would
have thrown away the entire pattern history for a gap that is, handled
properly, recoverable.

## What else was stale

- **`prod_readiness_plan.md` listed three infrastructure gaps as open; all
  three had shipped.** Postgres migration, persistent connection pool
  (`_get_pool()`'s `ThreadedConnectionPool`), external alerting
  (`engine/notifications.py`: desktop → webhook → log, where log always
  succeeds so nothing is silently dropped). Marked done in place — an item
  vanishing from a readiness list reads worse than one struck through. Its §2.2,
  the SQLite `open()` stall behind the 90-minute hang on 7/20, is marked
  resolved-by-architecture: there is no per-call file `open()` left to stall.
- **13 vetoes, not 15.** `rules/hard_vetoes.py` numbers its slots 1–16, #6 was
  never filled, and §54 removed `DAILY_LOSS` and `PROFIT_LOCK`.
- **13 UI tabs.** README said 9 in one place and 10 in another; both were counts
  taken at different times.
- **`engine/claude_brain.py` does not exist and never has** — it is in no commit
  in the history. README listed the NVIDIA NIM cascade as "still not wired into
  `scheduler.py`", which implies a module awaiting connection. The true half of
  that entry, unchanged: the pipeline calls no LLM automatically.
- **Portfolio heat — claim true, reason false.** Still un-normalized against
  account equity, which is real. But "no Robinhood balance API is called from
  Python by design" is not: `engine/account_sync.py`, `robinhood_sync.py` and
  `live_trader._buying_power()` all read it. Corrected in README, the
  `get_portfolio_heat` docstring and the UI tooltip.

## What was checked and left alone

`momentum_screen` and `insider_buying` are honest stubs — no market-wide
screening tool exists on any connected MCP, and `engine/screener.py` says so at
the call site. `options_expected_move_pct` and
`historical_earnings_move_avg_pct` are still placeholders, so `EARNINGS_RISK` is
in practice a pure days-to-earnings check, exactly as `rules_catalog.py`
documents. The 11-metric strategy health score and the named 10-step
orchestration layer were never built. `BUILD_FROM_SCRATCH_GUIDE.md`'s "stub it
for now" instructions are build-order guidance, not claims about the current
tree.

**Portfolio heat's denominator was deliberately not changed.** Heat feeds
position sizing, so re-basing it changes trade sizes on a system that is already
trading. That is a decision to take on purpose, not a side effect of a
documentation pass.

## Config / Database changes

None. `feature_schema` rides inside the existing `features` JSON blob — no
column, no migration, no backfill. Rows written before this release are
correctly interpreted by their absence of the key.

## Validation

- `python3 -m pytest -q` — **413 passed, 92 skipped, 3 errors** (the 3 are
  `TestClockSkew` unable to reach Postgres from the sandbox, unchanged from
  v2.3.2). Baseline before this work, same sandbox: 391 passed.
- `tests/test_feature_schema_migration.py` includes a test that disables the
  schema guard and asserts the misreading reappears — so the guard cannot later
  be deleted as dead code once every row carries the stamp.
- `tests/test_pattern_feature_wiring.py` asserts the **call site**, by reading
  `scheduler.py`'s source, not just the function. The v2.3.1→v2.3.2 lesson: a
  helper that works and is never called passes every behavioural test.
- `classify_change.py` → MINOR. `config_fingerprint` → `cc9a149613427f56`,
  unchanged.

## Rollback

```bash
./scripts/tp promote v2.3.2
```

Safe. Rows written under v2.4.0 carry `feature_schema: 2`, which v2.3.2's
encoder ignores as an unknown key — it reads their real ADX/CMF/sector RS as
ordinary values, which they are. The only loss is the missing-data handling for
older rows, i.e. the pre-audit behaviour.

  `./scripts/tp secrets set UI_AUTH_TOKEN`. Unchanged since v2.3.1.
- **The paper top-up is still pending** — `python3
  scripts/topup_paper_account.py --apply` has never run against Postgres. The
  Portfolio tab banner says so.
- **No runtime UI audit has been done.** Every finding in v2.3.1, v2.3.2 and
  this release came from static analysis and log reading; the Claude in Chrome
  extension never connected. The five renderers with `try`/`catch` but no shared
  error UI, and the WebSocket path, remain unexamined.
- `config_fingerprint` does not cover `risk.max_position_size_usd` — carried
  from v2.3.0.
- **The seven features are only real going forward.** Every existing closed
  pattern stays schema-1 and contributes nothing on those axes. The similarity
  search gets sharper as new rows accumulate, not retroactively.
