# v3.3.1 Release Notes

**Date**: 2026-07-27
**Priority**: Critical (Scheduler Race Condition Fix)
**Rollback**: `./scripts/tp promote v3.3.0`

---

## Summary

Fixes critical race condition where scheduled cycles were silently dropped when manual runs overlapped with scheduled fire times. This was discovered on 2026-07-27 when the 8 AM scheduled cycle was coalesced away by a manual run that started at 07:57.

---

## The Problem

**Incident**: 2026-07-27 08:00 ET
- Manual cycle starts: 07:57:26
- Manual cycle finishes: 08:00:44
- 8 AM scheduled cycle (should fire at 08:00:00): **MISSING**
- Next scheduled cycle never runs until manual trigger at 08:11:04

**Root Cause**: APScheduler's `coalesce=True` configuration silently coalesces (drops) scheduled slots that fire while a job is running.

---

## The Fix

### 1. Disabled Coalescing in APScheduler
**File**: `scheduler.py`, line 2093

```python
# Before:
id="trading_cycle", max_instances=1, coalesce=True,

# After:
id="trading_cycle", max_instances=1, coalesce=False,
```

**Effect**: Missed scheduled slots are now queued for execution instead of being silently dropped.

### 2. Added Database-Level Interlock
**File**: `scheduler.py`, lines 206-256

```python
if not force:  # Scheduled cycles only, not manual
    status = db.get_cycle_status()
    if status.get("is_running"):
        logger.info("Scheduled cycle skipped - another cycle is already in progress")
        return
```

**Effect**: Scheduled cycles skip if another cycle is running, preventing overlaps while allowing queued slots to execute in FIFO order after the current cycle finishes.

### 3. Added Scheduler Heartbeat Monitoring
**File**: `scheduler.py`, lines 2096-2115

```python
if job.last_execution_time:
    elapsed = (now - job.last_execution_time).total_seconds()
    expected_interval = interval * 60
    if elapsed > expected_interval * 1.5:
        logger.warning(
            f"Scheduler WARNING: Last cycle finished {elapsed / 60:.1f} min ago, "
            f"expected interval is {interval} min - cycles may be getting coalesced"
        )
```

**Effect**: Warns if cycles are taking longer than expected, enabling early detection of scheduler degradation.

---

## How It Works Now

**Scenario**: Manual run at 07:57, scheduled slot fires at 08:00

1. **07:57:26** - Manual run starts (force=True)
   - Bypasses DB interlock
   - Calls `run_supervised()`

2. **08:00:00** - 8 AM scheduled slot fires
   - With `coalesce=False`, slot is queued (not dropped)
   - `run_cycle(force=False)` checks DB
   - Manual run still in progress → `is_running=True`
   - Scheduled slot skipped with log message
   - Queued slot remains in APScheduler's queue

3. **08:00:44** - Manual run finishes
   - Calls `db.set_cycle_finished()` → `is_running=False`

4. **08:05:00** - Next scheduled slot fires
   - `run_cycle(force=False)` checks DB
   - No cycle running → `is_running=False`
   - Proceeds with cycle execution

**Result**: No silent scheduler death, no overlapping cycles, scheduled slots execute in order.

## Architecture Notes

**Why Two-Part Fix** (coalesce=False + DB interlock):

1. **`coalesce=False`** alone would allow scheduled slots to queue but could pile up if one is slow
2. **DB interlock alone** wouldn't help if scheduler drops the slots in the first place
3. **Together**: Slots queue AND are rate-limited to one-at-a-time

This is a **defense-in-depth** approach: if one mechanism fails, the other catches it.
